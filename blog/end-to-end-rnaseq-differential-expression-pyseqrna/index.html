End-to-End RNA-Seq: From FastQ QC to Splice-Aware Differential Expression with pySeqRNA

Analyzing high-throughput RNA sequencing is not just about running an aligner and counting reads; it requires understanding the mathematical distribution of count data and eliminating experimental confounders. Here is how pySeqRNA streamlines this end-to-end.

Why RNA-Seq Counts Are Not Normally Distributed

A common mistake among newcomers to transcriptomics is applying standard linear models (such as ANOVA or Student's t-test) directly to raw or FPKM-normalized read counts. RNA-Seq data consists of non-negative integer counts exhibiting two fundamental statistical properties:

1. Discrete Counting Process: Best approximated by a Poisson distribution at low counts, where variance equals the mean (σ² = μ). 2. Biological Overdispersion: In biological replicates, technical variability and inter-individual gene expression differences cause the variance to substantially exceed the mean (σ² = μ + α·μ², where α is the dispersion parameter).

Because of overdispersion, statistical packages like DESeq2 and edgeR model RNA-Seq counts using the Negative Binomial (Gamma-Poisson mixture) distribution. Accurately shrinking dispersion estimates across genes sharing similar expression levels is what gives modern differential expression analysis its statistical power.

The Danger of FPKM / RPKM in Comparative Analysis

While Reads Per Kilobase per Million mapped reads (RPKM) and Fragments Per Kilobase per Million (FPKM) normalize for gene length and library size, they fail to account for RNA composition bias.

If a single highly expressed gene (such as a viral coat protein or a muscle actin) accounts for 40% of the total sequencing reads in a diseased condition, all remaining genes will appear artificially downregulated simply because fewer sequencing reads were available to sample them.

Instead, robust pipelines apply median-of-ratios normalization (DESeq2) or Trimmed Mean of M-values (TMM, edgeR), which establish an invariant pseudo-reference across samples, preserving true biological fold changes.

Executing with pySeqRNA

We developed pySeqRNA to unify these best practices into a single reproducible Python CLI workflow with automatic quality control, STAR splice-aware mapping, count matrix generation, and differential expression:

pyseqrna-run \ --samples experimental_design_targets.txt \ --genome /ref/host_gallus_gallus.fa \ --gtf /ref/host_gallus_annotation.gtf \ --aligner star \ --de-tool deseq2 \ --padj-cutoff 0.05 \ --log2fc-cutoff 1.5 \ --threads 32 \ --generate-report

pySeqRNA automatically verifies paired-end strandness, removes low-expression noise (<10 counts across replicates), fits local dispersion trends, and outputs publication-ready volcano plots, clustered heatmaps, and Gene Ontology enrichment tables.

Diagnosing Confounders with PCA

Before interpreting individual differentially expressed genes, always inspect the unsupervised Principal Component Analysis (PCA) plot generated from variance-stabilized transformed (VST) counts.

If your primary biological condition (e.g., Infected vs. Mock) separates along PC1 (accounting for 50%+ of variance), your experiment was successful. If samples cluster instead by extraction date, sequencing lane, or technician, a severe batch effect is present.

In pySeqRNA, batch covariates specified in the experimental design targets file are directly included in the generalized linear model design matrix (~ batch + condition), statistically regressing out technical noise while preserving true biological effect sizes.
